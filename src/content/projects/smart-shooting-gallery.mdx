## Overview

The **Smart Shooting Gallery** is a full-stack cyber-physical system bridging custom electronics, embedded firmware, and real-time web applications. Physical target modules equipped with high-speed optical sensors and force transducers detect laser impulses and projectile impacts, registering hits within microseconds and broadcasting event telemetry across an MQTT broker to a spectator leaderboard.

## The Problem

Traditional recreational target systems are either entirely analog (requiring manual score tracking with no digital analytics) or built as closed arcade machines without cloud connectivity or real-time spectatorship. The challenge was to engineer an open, modular physical shooting gallery that:
1. Detects low-power pulsed laser hits and physical strikes with high temporal accuracy.
2. Rejects harsh ambient environmental light (overhead fluorescent lights, daylight) without missing fast laser pulses.
3. Transmits match telemetry over Wi-Fi with imperceptible latency to multi-screen spectator dashboards.

## Goals

- **Millisecond-Accurate Hit Detection**: Detect pulses down to 10 milliseconds using fast photodiode sensor arrays.
- **Physical Haptic Feedback**: Actuate micro-vibration motors and target LEDs immediately upon successful strike.
- **Dual-Sensor Noise Immunity**: Combine optical sensing with Force Sensitive Resistors (FSRs) to eliminate false triggers.
- **Real-Time Browser Dashboard**: Live scoreboard displaying reaction time, accuracy rate, and player rankings.

## Electronics & Sensor Decisions

Designing the physical sensing circuits required careful component selection:

1. **BPW34 Silicon PIN Photodiode**:
   - *Why chosen*: Features a 20ns rise time and broad spectral sensitivity (430nm to 1100nm), making it ideal for detecting visible red (650nm) laser pulses without sluggishness found in standard photoresistors (LDRs).
2. **Force Sensitive Resistors (FSR)**:
   - *Why chosen*: Provides analog pressure-to-resistance variance upon mechanical impact, allowing the system to distinguish light touches from high-velocity projectile strikes.
3. **Coin Vibration Haptic Actuators**:
   - *Why chosen*: Driven by NPN transistor switches (2N2222) with flyback protection diodes, providing instantaneous tactile confirmation to physical targets.

## Implementation Deep Dive

### 1. Analog Signal Conditioning & Interrupts
Direct analog-to-digital (ADC) polling is too slow for microsecond laser pulses. We implemented an external LM393 voltage comparator circuit with an adjustable potentiometer reference threshold. When the photodiode voltage spikes, the comparator pulls low, firing a hardware interrupt on the ESP32:

```cpp
// ESP32 High-Priority Interrupt Service Routine (ISR)
volatile uint32_t lastLaserHitMicros = 0;
const uint32_t DEBOUNCE_THRESHOLD_US = 80000; // 80ms window

void IRAM_ATTR onLaserDetectedISR() {
  uint32_t currentMicros = micros();
  if (currentMicros - lastLaserHitMicros > DEBOUNCE_THRESHOLD_US) {
    lastLaserHitMicros = currentMicros;
    portENTER_CRITICAL_ISR(&sensorMux);
    flagLaserHit = true;
    portEXIT_CRITICAL_ISR(&sensorMux);
  }
}
```

### 2. Dual-Core Task Pinning with FreeRTOS
The ESP32's dual-core Xtensa processor was utilized to separate time-critical sensing from network communications:
- **Core 1 (Sensory Loop)**: Dedicated strictly to ADC sampling of FSR pressure sensors, optical interrupt handling, and immediate haptic PWM triggering.
- **Core 0 (Network Loop)**: Connects to Wi-Fi, serializes JSON hit payloads, and manages MQTT publishing with automatic reconnection logic.

```cpp
// FreeRTOS Task Setup
xTaskCreatePinnedToCore(
  SensorPollingTask,   // Task function
  "SensorTask",        // Name
  4096,                // Stack size
  NULL,                // Parameters
  2,                   // High priority
  &xSensorTaskHandle,  // Handle
  1                    // Run on Core 1
);

xTaskCreatePinnedToCore(
  MqttPublishingTask,
  "MqttTask",
  4096,
  NULL,
  1,                   // Lower priority
  &xMqttTaskHandle,
  0                    // Run on Core 0
);
```

### 3. Sub-50ms Telemetry Relay Pipeline
Once an event is confirmed, the ESP32 publishes to topic `gallery/target/04/hit`. A lightweight Node.js gateway subscribes via MQTT, computes running score multipliers, and broadcasts the event over WebSockets to the React browser interface.

<Callout type="tip" title="WebSockets over HTTP Polling">
Using persistent WebSockets reduced message round-trip latency from ~280ms (polling) to ~38ms, creating an immediate, tactile response on the spectator leaderboard.
</Callout>

## Hardware Challenges & Engineering Solutions

### Challenge 1: Ambient Light Interference
- **Problem**: Overhead halogen and daylight flooded the BPW34 photodiodes, keeping the comparator triggered constantly.
- **Solution**: Implemented an optical bandpass filter tube over the diode and added a high-pass RC filter ($C = 100nF, R = 10k\Omega$) in the analog front-end to block steady DC ambient sunlight while passing sharp AC laser pulses.

### Challenge 2: Mechanical Frame Vibration Crosstalk
- **Problem**: Physical impacts on Target 1 rattled the mounting wood frame, triggering FSR readings on Target 2.
- **Solution**: Implemented silicone rubber isolation grommets on each target housing and combined FSR analog thresholds with optical beam validation (dual confirmation gate).
