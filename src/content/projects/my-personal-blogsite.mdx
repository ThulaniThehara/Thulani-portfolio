## Overview

This project is an experimental creative AI platform designed to investigate **human-AI co-creation**, **linguistic tokenization hurdles**, and **responsive UI/UX** within low-resource language generation — specifically focusing on poetic **Sinhala lyrics and songwriting**.

Standard conversational interfaces fail when authoring complex poetic structures in Sinhala due to token segmentation inefficiencies and a lack of rhythmic meter awareness. This platform provides an interactive studio where writers explore themes, rhyme schemes, and musical meters in real time.

## The Problem

1. **Non-Latin Token Fragmentation**: LLM tokenizers often split Sinhala Unicode characters into 3–6 fragmented byte tokens per character, causing high latency, repetitive generations, and high API token costs.
2. **Loss of Poetic Meter (Matra & Yati)**: Traditional Sinhala poetry and songwriting rely on strict syllable weight (`Matra`) and poetic pauses (`Yati`). Generic AI prompts disregard these cultural and linguistic rhythms.
3. **Clunky Chat Interfaces**: Standard chat box UIs force users into full-document regeneration rather than precise, stanza-level editing.

## Goals

- **Interactive Co-Creation Workspace**: Design a focused writing studio where writers can highlight verses and request localized variations or rhyme completions.
- **Phonetic & Rhyme Constrained Prompting**: Guide LLM inference to honor Sinhala phonetic endings and tonal moods.
- **Low-Latency Streaming UX**: Implement chunked streaming via Server-Sent Events (SSE) to preserve creative momentum.
- **High-Craft Visual Typography**: Optimize Sinhala font rendering and typography hierarchy for high digital readability.

## Implementation Deep Dive

### 1. Stanza-Level Targeted In-Filling UX
Rather than regenerating the entire song upon every prompt, the UI treats each verse as an independent stateful node. Writers can select a specific line and trigger contextual continuations:

```typescript
interface VerseBlock {
  id: string;
  stanzas: string[];
  rhymeScheme: 'AABB' | 'ABAB' | 'FREE';
  meterTarget: number;
  isStreaming: boolean;
}

// Inline streaming updater with zero layout shift
export function handleTokenChunk(verseId: string, newChunk: string) {
  setSongState((prev) => ({
    ...prev,
    verses: prev.verses.map((v) =>
      v.id === verseId ? { ...v, content: v.content + newChunk } : v
    ),
  }));
}
```

### 2. Overcoming Unicode Tokenization & Hallucination
To combat fragmented token generation in Sinhala, we implemented a two-step prompting strategy:
1. **Phonetic Romanized Pre-structuring**: The model constructs the poetic rhythm and rhyme constraints in a structured phonetic representation.
2. **Targeted Script Rendering**: A constrained mapping generates native Sinhala Unicode with high grammatical accuracy.

<Callout type="tip" title="Typography & Readability">
Complex conjunct characters in Sinhala scripts often suffer from clipping in standard web fonts. We customized line-height multipliers (`leading-[1.8]`) and paired `Noto Serif Sinhala` with `Plus Jakarta Sans` for clean bilingual legibility.
</Callout>

## Technical Challenges & Solutions

### Challenge 1: SSE Streaming Re-render Thrashing
- **Problem**: Updating React component state on every individual character token (10–30 events per second) caused laggy typing performance.
- **Solution**: Implemented an internal requestAnimationFrame debounce buffer that batches token chunks before pushing state updates to the DOM.

### Challenge 2: Poetic Rhyme Consistency in Sinhala
- **Problem**: The model frequently confused similar-sounding vowel signs (`්`, `ි`, `ී`, `ෙ`).
- **Solution**: Integrated a rule-based phonetic ending evaluator in the backend that scores generated line candidates against target rhyme categories before streaming final verses.
