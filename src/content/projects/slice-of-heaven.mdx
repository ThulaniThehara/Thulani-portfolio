## The Problem

Artisan food businesses rely heavily on visual appetite appeal and fresh stock management. However, typical e-commerce templates present major hurdles:
1. **Bloated Media Payloads**: High-resolution bakery photos caused sluggish page loading on mobile networks, leading to immediate visitor drop-off.
2. **Complex Product Customization**: Customers needed to specify custom cake messages, dietary substitutions (gluten-free, vegan), and pickup delivery time-slots during ordering.
3. **Inventory Race Conditions**: Simultaneous orders for limited-batch seasonal items frequently caused out-of-stock ordering errors.

## Goals

- **Lightning-Fast Visual Catalog**: Deliver high-definition culinary media with automated edge compression (WebP/AVIF).
- **Flexible Product Management**: Empower admins to manage complex variant pricing, dietary tags, and daily production quantities.
- **Frictionless Cart & Checkout UX**: Provide an interactive sliding cart with optimistic state updates and persistent storage.
- **Transactional Consistency**: Prevent over-ordering of limited baked items using database-level locking.

## Implementation Deep Dive

### 1. Relational Product & Variant Schema Design
Bakery items require multi-dimensional properties: categories, dietary flags, size variants, custom toppings, and daily batch limits. We modeled this cleanly in PostgreSQL with Prisma:

```prisma
model Product {
  id          String         @id @default(uuid())
  title       String
  slug        String         @unique
  description String
  basePrice   Decimal        @db.Decimal(10, 2)
  imageUrl    String
  isAvailable Boolean        @default(true)
  dietaryTags DietaryTag[]
  variants    ProductVariant[]
  category    Category       @relation(fields: [categoryId], references: [id])
  categoryId  String
  createdAt   DateTime       @default(now())
}

model ProductVariant {
  id         String   @id @default(uuid())
  name       String   // e.g. "6-Inch", "8-Inch", "Gluten-Free"
  priceDelta Decimal  @db.Decimal(10, 2)
  stockCount Int      @default(0)
  product    Product  @relation(fields: [productId], references: [id], onDelete: Cascade)
  productId  String
}
```

### 2. Automated Cloudinary Image Strategy
To ensure photos look appetizing while loading instantly, images are uploaded directly to Cloudinary and requested with dynamic query transformations:

```typescript
export function getOptimizedImageUrl(publicId: string, width = 600): string {
  // Automatically serves AVIF/WebP based on browser support + sharp compression
  return `https://res.cloudinary.com/sliceofheaven/image/upload/f_auto,q_auto,w_${width},c_limit/${publicId}`;
}
```

### 3. Persistent Cart State & Optimistic UI
A dedicated Zustand store handles the cart experience. When customers add items or adjust quantities, the UI updates instantaneously while validating stock in the background:

```typescript
export const useCartStore = create<CartStore>()(
  persist(
    (set, get) => ({
      items: [],
      addItem: (item) => {
        const current = get().items;
        const exists = current.find((i) => i.variantId === item.variantId);
        if (exists) {
          set({
            items: current.map((i) =>
              i.variantId === item.variantId ? { ...i, quantity: i.quantity + item.quantity } : i
            ),
          });
        } else {
          set({ items: [...current, item] });
        }
      },
      removeItem: (variantId) =>
        set({ items: get().items.filter((i) => i.variantId !== variantId) }),
      clearCart: () => set({ items: [] }),
    }),
    { name: 'slice-heaven-cart-v1' }
  )
);
```

<Callout type="tip" title="Stripe Webhook Idempotency">
To protect against duplicate order fulfillment if Stripe resends a webhook, all processed payment intent IDs are recorded in an idempotent transactions table before decrementing stock.
</Callout>

## Technical Challenges & Solutions

### Challenge 1: Flash Inventory Contention
- **Problem**: During holiday promotion drops, multiple customers attempting to check out the last box of artisan macarons simultaneously caused overselling.
- **Solution**: Implemented transactional inventory decrement with PostgreSQL checks (`stock_count >= requested_quantity`) inside an ACID transaction block, rolling back payment initialization if stock was exhausted.

### Challenge 2: Slow Mobile Network Image Rendering
- **Problem**: High-resolution gallery grids lagged on 3G/4G connections.
- **Solution**: Generated responsive HTML `srcset` attributes with low-quality image placeholders (LQIP) blurred into place before the full asset loaded.
