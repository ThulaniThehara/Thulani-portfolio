## Overview

**Enlear HRMS** is an enterprise human resource management platform architected on a 100% serverless foundation using AWS. Designed to replace disconnected third-party tools and error-prone spreadsheets, the system provides a unified operational dashboard for employee lifecycle management, attendance clocking, leave approvals, company device allocation, and internal HR policy Q&A.

## The Problem

Growing organizations face significant operational overhead when scaling HR processes:
1. **Scattered Employee Records**: Personal data, leave balances, and company hardware assignments lived across disparate spreadsheets without access control.
2. **Attendance Discrepancies**: Manual shift logging lacked real-time validation and caused downstream payroll friction.
3. **Repetitive HR Support Tickets**: HR staff spent hours answering standard questions about insurance coverage, leave entitlements, and company policies.
4. **Fragile Scaling**: Traditional server hosting incurred high maintenance costs while failing to scale smoothly during peak morning clock-in surges.

## Goals

- **Fully Serverless Infrastructure**: Build a low-maintenance, pay-per-use backend using AWS managed primitives.
- **Granular Role-Based Access Control**: Strict segregation across Administrators, Department Managers, and Employees.
- **Event-Driven Asynchronous Processing**: Offload heavy email dispatches, PDF generation, and notifications using message queues.
- **AI-Powered Self-Service**: Provide an integrated intelligent assistant to answer employee policy questions instantly.
- **High Test Reliability**: Maintain thorough test suites using Vitest for Lambda resolvers and business calculation logic.

## Implementation Deep Dive

### 1. Granular Authentication & RBAC with Amazon Cognito
To enforce role separation without querying the database on every HTTP request, user roles (Admin, HR Manager, Employee) and department scopes are embedded directly into Cognito JWT ID tokens via a Lambda Pre-Token Generation trigger:

```typescript
// AWS Lambda Pre-Token Generation Trigger
export const handler = async (event: any) => {
  const userId = event.request.userAttributes.sub;
  const userProfile = await fetchUserRoleAndPermissions(userId);

  event.response = {
    claimsOverrideDetails: {
      claimsToAddOrOverride: {
        'custom:role': userProfile.role,
        'custom:deptId': userProfile.departmentId,
        'custom:permissions': JSON.stringify(userProfile.permissions),
      },
    },
  };
  return event;
};
```

Within AppSync GraphQL resolvers, directives like `@aws_auth(cognito_groups: ["Admin", "HR_Manager"])` and custom resolver logic ensure employees cannot access restricted payroll or peer attendance data.

### 2. Event-Driven Notification System via Amazon SQS
When an employee submits a leave request or hardware issue, the primary AppSync Lambda resolver writes the state mutation to DynamoDB and promptly enqueues a message payload to an Amazon SQS FIFO queue:

```typescript
import { SQSClient, SendMessageCommand } from '@aws-sdk/client-sqs';

const sqsClient = new SQSClient({});

export async function dispatchLeaveEvent(payload: LeaveEventPayload) {
  const command = new SendMessageCommand({
    QueueUrl: process.env.NOTIFICATION_QUEUE_URL,
    MessageBody: JSON.stringify({
      eventType: 'LEAVE_SUBMITTED',
      recipientId: payload.managerId,
      metadata: payload,
      timestamp: new Date().toISOString(),
    }),
    MessageGroupId: `dept-${payload.departmentId}`,
    MessageDeduplicationId: `${payload.leaveId}-${Date.now()}`,
  });
  await sqsClient.send(command);
}
```

A dedicated worker Lambda processes queue batches in the background, formatting localized emails and dispatching company Slack webhooks without degrading front-end user latency.

### 3. Device & Asset Management Subsystem
To track distributed hardware (laptops, monitors, security fobs), we implemented an asset registry in DynamoDB:
- Assets are indexed by serial number, assignment status, and employee ID.
- When an employee offboards, an automated audit workflow flags all assigned hardware for return verification.

### 4. AI-Powered Policy Chatbot
To resolve common employee inquiries regarding leave policies, health insurance coverage, and reimbursement protocols, we integrated an intelligent conversational assistant:
- Policy documents are parsed and vectorized.
- The assistant retrieves relevant document clauses and formats concise, verified answers, significantly cutting down repetitive HR inquiries.

### 5. Rigorous Testing Strategy with Vitest
Leave calculations, prorated allowances, and complex tenure accrual algorithms are tested using Vitest with isolated mock event payloads:

```typescript
import { describe, it, expect } from 'vitest';
import { calculateProratedLeave } from './leaveCalculator';

describe('Leave Accrual Calculator', () => {
  it('should prorate annual leave correctly for mid-year joiners', () => {
    const joinDate = new Date('2024-07-01');
    const totalAnnualAllowance = 24;
    const result = calculateProratedLeave(joinDate, totalAnnualAllowance, 2024);
    
    expect(result.allowanceDays).toBe(12);
    expect(result.isProbationary).toBe(true);
  });
});
```

## Technical Challenges & Solutions

### Challenge 1: DynamoDB Single-Table Access Patterns
- **Problem**: Querying employee profiles alongside their active leave requests and device allocations required joining multiple data structures, which traditional NoSQL lacks.
- **Solution**: Designed composite partition keys (`PK: EMP#<id>`, `SK: PROFILE`), (`PK: EMP#<id>`, `SK: LEAVE#<date>`), and Global Secondary Indexes (GSIs) to fetch an employee and all associated sub-resources in a single targeted query.

### Challenge 2: Peak Clock-In Concurrency
- **Problem**: Hundreds of staff clocking in simultaneously between 8:55 AM and 9:05 AM risked causing database contention and Lambda cold starts.
- **Solution**: Leveraged DynamoDB on-demand capacity and configured provisioned concurrency on high-frequency clock-in resolvers, ensuring smooth sub-50ms execution.
